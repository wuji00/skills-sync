# 信息架构：目标 × 深度双轴

**先选网站目标**（决定访问者要完成什么任务），**再选内容深度**（决定页面数量、证据密度和维护成本）。选站型的本质是选「首屏放什么」。

通用铁律：
- **首屏三件事**：你是谁 / 你能干嘛（做过什么）/ 怎么找你。三行内讲完。
- **一个网站只设一个主目标**，最多加一个次目标；**首页只留一个主行动**，次行动最多一个。
- **倒金字塔**：最想被记住的放最上面，往下都是「还想了解更多的人」才会看到的。
- **每个 section 一个职能**，重复的信息合并成一处 + 内链。

## 轴一 · 七类网站目标

### A 求职转化

**适合**：正在求职、转型，希望招聘方快速判断「值得聊」的人。
**参考**：read.cv、Standard Resume、`<name>.dev` 个人页

首页顺序：
1. 姓名、目标角色、地点或工作方式（附求职状态标签）
2. 三项核心能力 / 职业价值主张
3. 精选经历与**量化成果**
4. 2–4 个相关项目
5. 简历下载、邮箱、职业社交链接

**详情页**：经历时间线、项目案例、关于。
**需要资料**：目标岗位、代表成果、技能证据、可公开的简历。
**避免**：冗长自传、与目标岗位无关的全部经历、没有上下文的技能进度条、用兴趣爱好抢版面。
**加分**：`@media print` 打印友好；经历条目「动词开头 + 结果结尾」。

### B 作品集展示

**适合**：设计师、开发者、摄影师、写作者、研究者、独立创作者。
**参考**：Bēhance 个人页、摄影师独立站、Awwwards 类站点

首页顺序：
1. 姓名、专业方向、作品主张
2. 3–6 个代表案例（大图优先，最少的文字）
3. 能力或服务范围
4. 简短经历与联系

**案例页结构**：问题 → 背景 → 我的角色 → 约束 → 过程（多图）→ 关键决策 → 结果 → 反思。
**需要资料**：高质量媒体、个人贡献说明、结果证据、可公开范围。
**避免**：只展示漂亮封面不说明本人做了什么；作品堆到几十个。
**加分**：图片压缩 + 懒加载 + 固定宽高比防跳版。

### C 个人介绍

**适合**：想有一个稳定的个人入口、跨职业介绍、轻量数字名片；没有成品可展示但故事完整的人。
**参考**：Derek Sivers 式自述、`/now` 页面运动

首页顺序：
1. 常用称呼 + 一句定位（「可以叫我 XX」）
2. 正在做什么
3. 3 个代表产出或身份切面（每个一句话说清在干嘛）
4. 兴趣（写「多久 + 到什么程度」，具体才有信息量）
5. 价值观 2–3 条（中英对照效果好，放最后收束）
6. 社交入口与联系

**需要资料**：简短介绍、当前关注、代表链接、联系方式。
**避免**：为了显得丰富而造空博客、空作品集、伪客户评价。
**加分**：第一人称口语；细节战胜形容词。

### D 长期记录

**适合**：持续写作、研究、做项目或记录生活的人。
**参考**：数字花园、`/uses` `/books` `/now` 页面家族

首页顺序：
1. 人物定位与当前主题
2. 最新或精选内容
3. **主题入口**（不是只按时间平铺）
4. 项目 / 文章 / 动态 / 书影音归档
5. 订阅与关于

**需要资料**：稳定内容源、分类方法、发布日期、未来更新流程。
**避免**：首页塞满按时间排列的全部内容却没有主题导航。
**加分**：每页显示「最后更新时间」；结构要能长期低成本维护（Markdown 直出优先）。

### E 咨询获客

**适合**：顾问、教练、自由职业者、工作室、提供专业服务的人。

首页顺序：
1. **为谁解决什么问题**
2. 服务类型与适用情境
3. 方法或合作流程
4. 案例、结果、评价
5. 常见问题
6. 预约 / 邮件 / 需求表单

**需要资料**：目标客户、服务边界、案例、可信证明、合作方式与报价区间。
**避免**：只写个人经历，不说明客户为什么现在要联系你。
**注意**：评价（Testimonial）必须有 `permission` 字段确认过才能放。

### F 创作者主页

**适合**：多平台发布内容、经营社群、课程、产品或接商务合作的人。
**参考**：Linktree 升级版、播客主页、Newsletter 作者页

首页顺序：
1. 创作主题与受众承诺 + 可验证数字（粉丝 / 阅读 / 期数，注明统计时间）
2. 精选内容或系列（标出数据：10万+、精选）
3. 产品、课程、社群或订阅
4. **各平台入口及内容差异**（说清「在这里我发什么」）
5. 商务合作与联系（写清适合谁 + 怎么开始）

**避免**：只放一排社交图标让访问者自己猜每个平台有什么。

### G 独立开发者

**适合**：上线过产品、有开源项目，想让人用起来 / 订阅 / 付费的人。

首页顺序：
1. 我是谁 + 做了几款产品 + 累计用户数
2. 产品列表（名称 / 一句话 / 状态 / 用户数 / 可点进去用的链接）
3. 浏览器里直接能用的小工具
4. 开源仓库 + Star + 一句话
5. 构建日志 / 博客
6. 关于与联系

**加分**：诚实标注已下线的项目（反而加分）；把累计用户 / Star / 上线数量放首屏。

## 轴二 · 内容深度

### L1 名片层
**形态**：单页或极少页面。
**最低资料**：身份、定位、主行动、联系方式、3 个代表链接。
**适合**：快速上线、资料较少、临时介绍或活动页。

### L2 证明层
**形态**：首页 + 项目 / 经历 / 作品详情页。
**额外需要**：个人贡献、背景、过程、成果、时间线、媒体素材。
**适合**：求职转化、作品集、咨询获客。

### L3 内容系统层
**形态**：首页 + 详情页 + 分类索引 + 归档 + 持续更新机制。
**额外需要**：稳定内容源、分类规则、封面、发布日期、更新责任人。
**适合**：长期记录、创作者主页、多产品或多服务网站。

**降级规则：资料达不到 L2 就先上线 L1，不用占位案例凑数；内容不足以持续更新就不要选 L3。**

## 方案输出模板

给用户 2–3 套方案时用统一格式，方便横向比较：

```markdown
## 方案名：目标 × 层级（例：创作者主页 × L2）

- 适合：
- 首屏传达：
- 主行动：
- 导航：
- 首页顺序：
- 详情页：
- 使用现有资料：
- 还需补充：
- 主要取舍：
```

**差异必须来自访问者任务和内容重点，不能只是栏目改名。** 最后明确推荐一套并说明理由。

## 组合规则

- 主目的定首屏：只有一个 Hero，服务一个目的。
- 次目的降级成首页 teaser：标题 + 3 条 + 「查看全部 →」内链到二级页。
- 二级页各自完整：`/products/`、`/blog/`、`/about/`、`/services/` 各是一个完整的 A–G 单元。
- 顶栏导航 4–6 条，超过就合并。
- **求职与咨询并存时分设清晰入口**，不要在同一首屏混合两套承诺。
- 作品很多时按代表性和相关性精选，完整归档放二级页。

混合示例（F + G + C，即本 skill 的原型站，创作者主页 × L3）：
```
首页 Hero（创作者定位 + 数字）
 → 合作 teaser（4 张卡）→ 产品 teaser（3 条）→ 工具 teaser（3 条）→ 博客 teaser
 → 二级页：/services/ /products/ /tools/ /blog/ /skill/ /about/
```
