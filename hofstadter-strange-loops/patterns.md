# 模式与技术 (Patterns & Techniques)

每条: **When to use** / **How** / **Trade-offs**.

---

## 1. WU 推理法 (WJU Puzzle)

**When**: 引入形式系统; 培养"系统外看系统"的直觉。
**How**:
1. 选符号集 {W, J, U} (实际 WJU 三字符)
2. 公理: WJU
3. 推理规则: R1 加 J; R2 三 J → U; R3 WU → 无; 等等
4. 从 WJU 出发枚举推导; 看是否可达目标
**Trade-offs**: 形式极简, 不能讲大道理, 适合作为"小练习"建立符号肌肉。

---

## 2. MU 推理法 (MIU System)

**When**: 引入不可判定性直觉; 形式系统有边界。
**How**:
1. 字符集 {M, I, U}; 公理 MI
2. 规则: 串末加 U; Mx → Mxx; 三连续 I → U; UU → 删除
3. 问: MU 可达否? 答案: 否 (证: 数 I 数 mod 3 不变)
**Trade-offs**: 比 WJU 稍复杂, 但能讲清楚"存在性否定"。

---

## 3. 哥德尔编码 (Gödel Numbering)

**When**: 把"句"变成"数"; 构造自指系统的必备工具。
**How**:
1. 给每个基本符号编一个互素整数 (例如: 0→1, s→2, =→3, +→5, ×→7, (→11, )→13)
2. 编码串: 把符号的编码连乘 (prime^k × code^k)
3. 任意句 → 唯一自然数
4. 反向: 唯一分解定理保证唯一解码
**Trade-offs**: 解码复杂度高 (要做素因数分解), 但自指代价是必要的 — 这是系统看到自身句法的入口。

---

## 4. 对角线自应用 (Diagonal Self-Application)

**When**: 任何"系统内不可判定"构造。
**How**:
1. 取系统的自应用算子 diag(x) = "把 x 嵌入到自身模版"
2. 构造 f(x) = "x 不可证" 这种否定自指
3. 让 x = f(diag(x)) → 自我引用闭环
4. 假设系统能证 f(x), 推出矛盾 (系统内可证 p 与 ¬p)
**Trade-offs**: 步骤精炼但需要严格数学训练; 教学时多用类比 (印刷品悖论) 先行。

---

## 5. TNT 印符串构造 (Typographical Number Theory)

**When**: 演示"形式系统内表达自然数"。
**How**:
1. 0: 字符串 "0"
2. n+1: "Sn0"
3. 加法: "aSb0Sa0" 类型的表达 (此为简记)
4. 乘法: 类似, 用字符嵌套
5. 命题: 用 = 与 ~ 与 ∀
**Trade-offs**: 表达式极长 (例如 100 = SSSSS…S0), 但这就是"符号无捷径"的演示。

---

## 6. 同构识别三步法 (Isomorphism Spotting)

**When**: 跨领域看到"同一形状"。
**How**:
1. 抽象: 抽出两边系统的"基本元素 + 组合规则"
2. 映射: 找两边元素的对应关系
3. 验证: 看两边"关系是否保留"
**Trade-offs**: 任何一半都难; 简单同构一眼看出, 复杂同构要训练。

---

## 7. 三层可计算性 (BlooP / FlooP / GlooP)

**When**: 演示"递归层级"与"可计算性边界"。
**How**:
1. BlooP: 只有 LOOP (有界循环); 可证终止
2. FlooP: 加 WHILE (无界循环); 可能不终止; 等于图灵机
3. GlooP: 包含"是否能停?"问题; 不可判定
**Trade-offs**: 三层对应三种能力, 不只是复杂度层级; 教学时配停机问题证法。

---

## 8. 跳出系统法 (Jumping Out of the System)

**When**: 发现"系统内规则不够用"或"无法判断全局"时。
**How**:
1. 暂停系统内推理
2. 在元层定义"系统行为"的描述 (类似自描述程序)
3. 用元层陈述"系统在某种意义下不完备"
4. 必要时再跳出元层 → 元元层
**Trade-offs**: 元层越高, 与内层证据的连接越弱; 别无限逃逸。

---

## 9. 自描述程序 (Quine)

**When**: 演示"代码引用自身"; 同构 G 句。
**How**:
1. 写一个函数 Q, 它能输出自己的源代码
2. 经典技巧: Q = char(34) + Q + char(34) + rest
3. 把 Q 当数据再用 char(34) 包裹
**Trade-offs**: 实现细节依赖语言; 不同语言复杂度不同 (Python 短, C 长)。

---

## 10. 对话体论证 (Dialogue Argument)

**When**: 把哲学论证包装得可读; 教学场景。
**How**:
1. 选角色 (乌龟 + 阿基里斯 + 螃蟹 + 甲虫)
2. 给每个角色一种思维倾向 (乌龟 = 怀疑 / 阿基里斯 = 直觉)
3. 用对话展示推理冲突 + 化解
4. 重要论证必须有形式化回声 (脚注 / 附图 / 形式系统)
**Trade-offs**: 形式化藏起来让读者以为只是故事; 真正的论证在脚注。

---

## 11. 多声部类比 (Fugue / Canon as Proof)

**When**: 让读者直觉理解"并行推导"。
**How**:
1. 一主题 = 一个定理
2. 一声部应答主题 = 在另一推导路径下证明同一命题
3. 卡农: 一声部主题 + 一延时复制
4. 螃蟹卡农: 倒行; 对应对偶命题
**Trade-offs**: 比喻直观, 但要让读者知道"音乐结构 ≠ 形式规则"。

---

## 12. 印刷品悖论解读 (Escher's Print Gallery Walkthrough)

**When**: 视觉化怪圈; 训练跨层直觉。
**How**:
1. 画中心空白 → 引入"中心是另一张画"的递归
2. 空白处画廊 → 画廊里有看画的人
3. 人看画 → 画里有空白 → 又是一张画 → 无限
4. 解释: 不是错误, 是"无限缩进的自指"
**Trade-offs**: 视觉图像比文字更有冲击力, 但需要解释"为什么合法"。

---

## 13. 元层叠加 (Meta-Stacking)

**When**: 设计自省系统; 让智能体"思考自己的思考"。
**How**:
1. 把"对象"与"关于对象的话"分两层
2. 允许在元层用对象层的语法 (但要标记)
3. 不混层写规则
4. 元层可再有元层 — 直到无限
**Trade-offs**: 无限元层导致工程上无意义; 实践取 2-3 层足够。

---

## 14. 编码-解码一致性 (Encoding-Decoding Consistency)

**When**: 用 Gödel 编码时; 检查自指是否完整。
**How**:
1. 编码函数 inject: 串 → 数
2. 解码函数 project: 数 → 串
3. 必须有 project(inject(s)) = s
4. 必须有 inject 互不冲突 (不同串 → 不同数)
**Trade-offs**: 用 prime powers 保证互不冲突; 复杂度 O(n log n) per 串。

---

## 15. 缠结识别 (Tangled Recognition)

**When**: 评估"层次"系统是否真清晰; 找反例。
**How**:
1. 列出系统的声称层级 (硬件 / OS / 应用 / 用户)
2. 在每一层找一个"反向影响"的例子 (用户改硬件? 应用改 OS?)
3. 反例出现 → 缠结
4. 缠结不一定是 bug, 但要承认"层级"只是图, 不是物理
**Trade-offs**: 容易被"设计意图"误导; 缠结通常在运行中显现。

---

## 16. 自复制同构 (Self-Reproduction Mapping)

**When**: 把生物 / DNA / 程序 / 语言自指统一到同一框架。
**How**:
1. 抽出"载体" (DNA 链 / 程序源码 / 形式系统公理)
2. 抽出"读出机制" (核糖体 / 解释器 / 推理引擎)
3. 抽出"复制指令" (双螺旋 / Quine / 自应用)
4. 比对三个角色是否同构
**Trade-offs**: 抽象层次高, 可能误把"类似"当"同构"; 要严格验证每步映射。

---

## 17. 不可判定的构造范式 (Undecidability Pattern)

**When**: 任何"系统内不可判定"问题的构造 (停机、丘奇、塔斯基)。
**How**:
1. 假设系统能判定 P
2. 用判定器构造一个把 P 当子例程的对角线实例 D
3. 让 D 攻击自己 (D 自己的输入是 D 的源代码)
4. 矛盾 → 假设错 → P 不可判定
**Trade-offs**: 步骤机械; 但需要严格写出对角线实例, 工程上易出错。

---

## 18. 跨层映射时的"残余差异"识别

**When**: 把"同构"用在工程中 (例如用巴赫结构解释代码)。
**How**:
1. 列出两系统的"声称对应"
2. 标出每个对应中"实际差异" (音色 vs 数据类型, 节奏 vs 控制流)
3. 差异不影响主论证时标"无害"
4. 差异影响时标"危险" — 不可迁移
**Trade-offs**: 承认差异会削弱类比的说服力; 但保真度更重要。

---

## 19. 形式系统的"边界陈述"

**When**: 想说"系统 S 不能表达 X"。
**How**:
1. 把 X 形式化 (成语言可表达的命题)
2. 证明 X 不在 S 的可表达集内 (反证 / 对角线)
3. 注意: 不可表达 ≠ 不可思考 (塔斯基不可定义真理性)
**Trade-offs**: 易把"不可表达"夸大成"不存在"; 形式边界 ≠ 现实边界。

---

## 20. 禅宗公案作论证 (Zen Koan as Argument)

**When**: 哲学论证触及"言说极限"时 (ch09 用"无门关"对应哥德尔)。
**How**:
1. 选一句公案 (例: "无")
2. 让读者尝试用形式语言翻译
3. 显示"形式语言无法完全捕捉"
4. 把这"无法完全捕捉"对应到哥德尔定理
**Trade-offs**: 跨文化引用, 部分读者不接受; 但作为"言说极限"隐喻有效。

---

## 21. 论证-故事双层结构 (Dual-Layer Argument)

**When**: 写严肃但可读的哲学 / 数学散文。
**How**:
1. 故事层: 用角色对话承载论证骨架
2. 论证层: 故事结束后用形式语言 / 定理严格证明
3. 两层互相回响: 故事的某对话 = 论证层的某步
**Trade-offs**: 工程上多倍工作量; 但读者的获得感也是多倍。

---

## 22. 范畴论风格的"对象 vs 态射"对照

**When**: 在多领域讲"同构"时 (侯世达后期常用)。
**How**:
1. 一边讲"对象"是什么
2. 一边讲"对象间关系"是什么 (态射)
3. 同构 = 两侧对象集 + 态射集都一一对应
4. 不严格用范畴论术语, 但保留其逻辑
**Trade-offs**: 范畴论术语吓跑读者; 隐藏其逻辑更亲民, 但失去精度。
